# ممیزی سرعت و رابط جستجو/فیلتر سرویس‌یار

## یافته و اصلاح عملیاتی
- در HTML قبلی فایل `/assets/operations.js` (حدود ۶۰۰ کیلوبایت) حتی در صفحه عمومیِ بدون نشست معتبر بارگذاری می‌شد.
- اکنون `frontend/assets/app.js` پس از احراز هویت از تابع `ensureOperationsModule()` استفاده می‌کند. فقط یک درخواست برای اسکریپت اجرا می‌شود و پیش از `render()` عملیات لازم آماده است؛ خطای دریافت، امکان تلاش مجدد دارد.
- آیکن مرورگر از `favicon.svg` محلی استفاده می‌کند، نه `logo.png` چندصد کیلوبایتی.
- کتابخانه نقشه نشان، Leaflet، فونت و موتور PDF طبق ممیزی مرحله قبل محلی هستند.

## قرارداد طراحی فیلترها
- یک فایل سبک `frontend/assets/filter-consistency.css` بعد از تم اصلی و فایل `ui-consistency.css` بارگذاری می‌شود.
- محدوده: جستجوی عمومی فهرست‌ها، مدارس، دانش‌آموزان، سرویس‌ها، فاکتورها، گزارش‌ها، حسابداری و بدهکاران نمایندگان.
- فاصله استاندارد حدود ۸ تا ۱۲ پیکسل، ارتفاع کنترل‌ها حداقل ۴۲ پیکسل، متن ورودی ۱۴ پیکسل و برچسب ۱۳ پیکسل.
- در موبایل، کنترل‌ها در عرض باقی‌مانده جمع می‌شوند و فرم‌های کاوه‌نگار تک‌ستونه خواهند شد.
- UI موجود و API جستجو دست‌نخورده باقی مانده‌اند؛ مدیریت نقش‌ها، اعتبارسنجی بک‌اند و نتیجه فیلتر نباید با تغییر CSS عوض شوند.

## آزمون‌ها
```sh
node tests/filter-consistency.cjs
node tests/lazy-operations.cjs
node tests/ui-consistency.cjs
node tests/kavenegar-sms-contract.cjs
php tests/kavenegar-sms.php
```

## موارد نیازمند آزمون مرورگر
- بارگذاری اولیه مهمان و بررسی اینکه `operations.js` در Network وجود ندارد.
- ورود با رمز، ورود OTP نگین/کاوه‌نگار (تنها با کلید آزمایشی واقعی و مجوز ارسال)، بازیابی نشست و ورود نیابتی.
- کنترل تمام فیلترها در عرض‌های ۳۶۰، ۳۹۰، ۷۶۸ و ۱۴۴۰ پیکسل؛ عملکرد پنجره‌ها و انتخاب‌گر مدرسه.
- اندازه‌گیری واقعی Total Blocking Time، LCP، تعداد درخواست و تأخیر در بارگذاری داشبورد قبل و بعد از تغییر.

موفقیت CI به‌تنهایی تأیید بصری و کارکرد واقعی سرویس پیامکی نیست.
