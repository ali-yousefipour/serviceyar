# مدیریت روش‌های ورود در سرویس‌یار

## سه روش ورود
صفحه ورود بر اساس `GET /api/v1/auth/methods` فقط گزینه‌های مجاز و آماده را نمایش می‌دهد:
- نام کاربری و رمز عبور (`POST /api/v1/auth/login`)
- نام کاربری + کد یک‌بارمصرف پیامکی (`POST /api/v1/auth/sms/request` و `/verify`)
- نام کاربری + کد ربات بله (`POST /api/v1/auth/bale/request` و `/verify`)

در «ادمین کل ← تنظیمات سامانه ← روش‌های ورود کاربران» مدیر کل می‌تواند سه چک‌باکس را به‌صورت مستقل فعال/غیرفعال کند. API با `PUT /api/v1/admin/login-methods` و CSRF به‌روزرسانی می‌شود و حداقل یک روش آماده را الزامی می‌کند. **سیاست‌ها در سرور اعمال می‌شوند**، نه فقط در صفحه مرورگر.

## فعال‌سازی پیامک
اطلاعات سرویس نگین از مسیر «ادمین کل ← تنظیمات سامانه ← تنظیمات سرویس پیامک نگین» قابل ثبت و مدیریت است. نام کاربری و رمز عبور در جدول تنظیمات سامانه به‌صورت رمزگذاری‌شده ذخیره می‌شوند و API هیچ‌گاه مقدار رمز را برنمی‌گرداند. برای تغییر اطلاعات، هر دو کادر نام کاربری و رمز را تکمیل کنید؛ خالی گذاشتن هر دو، اطلاعات قبلی را حفظ می‌کند. وضعیت فعال‌بودن سرویس و افزونه PHP `SOAP` در همان بخش نمایش داده می‌شود. در صورت نیاز، مقادیر `NEGIN_SMS_ENABLED`، `NEGIN_SMS_USERNAME` و `NEGIN_SMS_PASSWORD` در `.env` فقط نقش مقدار جایگزین را دارند و تنظیمات ذخیره‌شده در دیتابیس بر آن‌ها اولویت دارد. پیامک به فیلد `users.mobile` در پروفایل کاربر فعال ارسال می‌شود؛ شماره به 09 استانداردسازی می‌شود. ابتدا مهاجرت `database/migrations/0111_sms_login.sql` را اجرا کنید یا در ادمین کل گزینه پیامک را فعال و ذخیره کنید تا در صورت داشتن مجوز `CREATE TABLE` جدول‌ها ایجاد شوند.

کدها تصادفی شش‌رقمی، با هش رمز یک‌طرفه ذخیره و پس از ۵ دقیقه منقضی می‌شوند. درستی کد حداکثر طی پنج تلاش بررسی می‌شود؛ محدودیت درخواست در هر IP و برای هر کاربر برقرار است. پاسخ ارسال، وجود حساب یا شماره تلفن را افشا نمی‌کند؛ «درخواست پذیرفته شد» به معنی تحویل پیامک نیست.

## انتخاب درگاه پیامک (نگین یا کاوه‌نگار)

در «ادمین کل ← تنظیمات سامانه ← روش‌های ورود کاربران»، بخش «تنظیمات پیامک کاوه‌نگار» و «انتخاب درگاه اصلی ارسال پیامک» اضافه شده است. تا زمانی که مدیر کل درگاه را تغییر ندهد، **نگین به‌عنوان پیش‌فرض حفظ می‌شود**.

برای فعال‌سازی کاوه‌نگار:
1. کلید API کاوه‌نگار را در بخش مربوط ثبت کنید؛ شماره فرستنده اختیاری است و باید مطابق خط ارسال مجاز حساب باشد.
2. «فعال‌سازی حساب کاوه‌نگار» را ذخیره کنید. کلید به‌صورت AES-256-GCM، با کلید خصوصی موجود در `storage/private` رمزگذاری شده و به مرورگر بازگردانده نمی‌شود.
3. پس از آماده‌شدن PHP cURL و دریافت وضعیت «آماده»، از فهرست «درگاه اصلی» کاوه‌نگار را انتخاب و ذخیره کنید.
4. ورود با کد پیامکی، ورود با موبایل، بازیابی رمز و ارسال پیامک‌های صف از **همان درگاه منتخب** استفاده می‌کنند؛ فرایند ارسال خودکار به درگاه دوم برنمی‌گردد تا پیام تکراری ارسال نشود.

APIهای مدیریتی با احراز هویت ادمین کل و CSRF: `GET/PUT /api/v1/admin/kavenegar-sms` و `GET/PUT /api/v1/admin/sms-provider-selection`. فعال‌سازی صرفاً تنظیمات را ثبت می‌کند و **پیامک آزمایشی واقعی به هیچ شماره‌ای ارسال نمی‌کند**.

کلید API را فقط در صفحه تنظیمات امن وارد کنید؛ هیچ‌گاه کلید را در URL عمومی، متغیر JavaScript، مخزن یا پیام‌های لاگ درج نکنید. نگهداری `storage/private/negin-sms.key` برای رمزگشایی کلیدهای هر دو سرویس ضروری است. درگاه REST رسمی کاوه‌نگار: `https://api.kavenegar.com/v1/{API_KEY}/sms/send.json`. مستندات: https://kavenegar.com/sdk.html

## فعال‌سازی بله
ربات باید در ادمین کل تنظیم و به حساب کاربری متصل باشد. کاربر عادی شماره همراه خود را از دکمه اشتراک شماره بله تأیید می‌کند؛ ادمین کل نیازمند کد اتصال ویژه پروفایل است. تأیید کد بله نیز تابع چک‌باکس مدیریت ورود است.

## نکات عملیاتی
- اگر SMS یا Bale هنوز پیکربندی نشده باشد، حتی با فعال بودن چک‌باکس آن روش در صفحه ورود نمایش داده نمی‌شود.
- مدیریت تنظیمات فقط برای نقش `super_admin` مجاز است؛ URL عمومی تنظیمات فقط بولین فعال/آماده بودن را برمی‌گرداند.
- تا قبل از تأیید کارکرد مسیرهای جایگزین در محیط واقعی، روش رمز عبور را غیرفعال نکنید.
- در صورت خطای ارسال، تنظیمات نگین، افزونه SOAP، لاگ API و migration را بررسی کنید. هیچ کدی نباید در لاگ ثبت شود.
