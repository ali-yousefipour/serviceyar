# ربات بله سرویس‌یار — راهنمای راه‌اندازی

## محدوده قابلیت‌ها
این اتصال مستقل از پرداخت کیف پول بله است:
- ادمین کل: ذخیره توکن، فعال/غیرفعال‌کردن ربات، ثبت وب‌هوک، بررسی اتصال واقعی و خطاهای وب‌هوک
- هر کاربر: اتصال یا قطع ارتباط بله از پروفایل با دستور یک‌بارمصرف `/start CODE`
- ورود: نام کاربری → ارسال OTP شش‌رقمی به گفتگوی خصوصی بله متصل → تأیید OTP → نشست عادی سرویس‌یار
- مدیر شرکت: ارسال پیام متنی به حساب بله متصل کاربران شرکت
- ربات: پاسخ به `/start` و `/help` و اتصال حساب با کد

ارسال انبوه به والدین/رانندگان یا پیام‌های خودکار رخدادها **در این نسخه فعال نیست**؛ این عملیات نیازمند ثبت رابطه هویت/رضایت برای مخاطبان غیرکاربر و زیرساخت صف تحویل مستقل است.

## پیش‌نیازها
1. بازوی مستقل برای سرویس‌یار در بله ایجاد کنید؛ از توکن ربات پرداخت کیف پول استفاده نکنید.
2. فایل محیط سرور (خارج از Git) را تنظیم کنید:
   - `APP_URL=https://challi.ir` (بدون مسیر انتهایی)
   - `BALE_SETTINGS_KEY=<random secret 32+ chars>` (ثابت و محرمانه)
   - SSL/HTTPS و امکان درخواست خروجی HTTPS از سرور به `tapi.bale.ai`
3. مهاجرت `0110_bale_bot_auth.sql` را طبق رویه پروژه اجرا کنید. در اولین ذخیره تنظیمات، سامانه تلاش می‌کند جدول‌های مشخص را در صورت نبود ایجاد کند؛ اگر دسترسی CREATE وجود نداشت اجرای دستی مهاجرت الزامی است.
4. از «تنظیمات سامانه ← ارتباطات و سرویس‌ها ← ربات بله» توکن را ثبت و گزینه فعال‌سازی را انتخاب کنید. توکن پس از تأیید `getMe` با AES-256-GCM ذخیره می‌شود؛ مقدار آن در API و HTML بازگردانده نمی‌شود.
5. روی «بررسی وضعیت» کلیک کنید؛ اتصال واقعی و آدرس وب‌هوک با `getWebhookInfo` بررسی می‌شود.

## اتصال و ورود
- کاربر وارد سایت می‌شود، «ویرایش پروفایل» را می‌زند و کد اتصال می‌گیرد.
- کد به مدت ۱۰ دقیقه معتبر است. در گفتگوی خصوصی ربات دستور `/start <code>` را ارسال می‌کند.
- پس از تأیید اتصال، در صفحه ورود گزینه «ورود با پیام‌رسان بله» را می‌زند.
- کد شش‌رقمی پنج دقیقه اعتبار دارد؛ حداکثر پنج حدس برای هر کد و پنج درخواست برای هر کاربر در ۱۵ دقیقه و ده درخواست برای هر IP در ۱۵ دقیقه مجاز است.
- خروج از حساب، نشست را مانند ورود با رمز باطل می‌کند. قطع اتصال بله مانع صدور کدهای ورود جدید می‌شود.

## API داخلی
- `GET /api/v1/auth/bale/status` — عمومی، وضعیت فعال‌سازی
- `POST /api/v1/auth/bale/request` — عمومی، درخواست OTP
- `POST /api/v1/auth/bale/verify` — عمومی، تأیید OTP و ساخت نشست
- `GET|POST|DELETE /api/v1/bale/link` — نشست معتبر، POST/DELETE با CSRF
- `POST /api/v1/bale/message` — مدیر مجاز؛ `recipientId` و `text`؛ CSRF
- `GET|PUT /api/v1/admin/bale-bot` — ادمین کل؛ PUT با CSRF
- `GET /api/v1/admin/bale-bot/check` — بررسی زنده برای ادمین کل
- `POST /api/v1/bale/bot/webhook/<secret>` — ورودی بله با مسیر محرمانه ۲۵۶ بیتی

## تست عملی پس از استقرار
1. تأیید موفق CI و Deploy جدیدترین `main`.
2. ثبت توکن معتبر و مشاهده نام ربات؛ بررسی زنده وب‌هوک با وضعیت صحیح.
3. ایجاد کد اتصال برای کاربر آزمایشی؛ ارسال دستور `/start` و دریافت پیام تأیید.
4. درخواست OTP و ورود موفق؛ آزمایش OTP اشتباه، انقضا و تکرار.
5. ارسال پیام تست از مدیر شرکت به کاربر متصل و اطمینان از وصول.
6. قطع اتصال و اطمینان از عدم ارسال OTP/پیام به آن حساب.
7. کنترل اینکه توکن ربات از طریق Network مرورگر، پاسخ API، لاگ‌ها یا HTML افشا نمی‌شود.

**مهم:** ذخیره فایل `.env` روی هاست باید پایدار بماند؛ تغییر `BALE_SETTINGS_KEY` یا تغییر مقدار رمزی که هنگام ذخیره توکن به‌عنوان fallback استفاده شده، باعث نامعتبرشدن رمزگشایی توکن خواهد شد.

## تنظیم درگاه کیف پول بله از پنل
در همان پنل ادمین کل، دو ورودی محرمانه مستقل وجود دارد:
- «توکن ربات بله» برای API پیام‌رسان/ورود و صدور فاکتور
- «توکن ارائه‌دهنده کیف پول بله» برای `provider_token` در `sendInvoice`

هر دو توکن در پایگاه داده به شکل AES-256-GCM رمزگذاری می‌شوند و در پاسخ تنظیمات افشا نمی‌شوند. خالی گذاشتن فیلد به معنی حفظ توکن قبلی است. تغییر توکن ربات پیش از ذخیره با `getMe` بررسی می‌شود؛ پس از فعال‌سازی وب‌هوک مشترک ثبت و با «بررسی وضعیت» قابل استعلام است. پرداخت‌های `pre_checkout_query` و `successful_payment` قبل از پیام‌های متنی به مسیر مستقل تسویه پرداخت هدایت می‌شوند.

**برای پیش‌فرض محرمانه** از فایل `.env` امن هاست یا فیلدهای پنل ادمین استفاده کنید. توکن زنده نباید در Git، فایل‌های عمومی، تصویر خطا، seed دیتابیس یا مستندات قرار گیرد. API پیام‌رسانی تنها ثبت وب‌هوک و تماس‌های `getMe` را اعتبارسنجی می‌کند؛ تراکنش مالی واقعی باید با فاکتور آزمایشی کنترل‌شده و استعلام موفق بله بررسی شود و نباید وصول جعلی ثبت شود.
