# ممیزی مرحله ۱ — معماری، قرارداد API و آماده‌سازی استقرار

تاریخ بررسی: ۲۰۲۶-۱۱-۲۲. مبنا: شاخه `main` در زمان بررسی.
این گزارش ممیزی مخزن است؛ جایگزین پروفایل عملکرد واقعی، آزمون نفوذ یا تأیید هاست عملیاتی نیست.

## موجودی مخزن

- ۳۴۱ فایل در درخت Git؛ از جمله ۱۳۶ فایل PHP، ۶۵ SQL، ۱۴ JS، ۴۲ CJS، ۲ MJS و ۱۰ CSS.
- مسیر ورود API: `backend/public/index.php`؛ هسته دامنه و مالی: `backend/src/Domain/`.
- مدیریت هویت: `backend/src/Auth/`؛ کاربران: `backend/src/Users/`؛ خروجی: `backend/src/Reports/`.
- ورود و رابط: `frontend/index.html`، `frontend/portal.html` و `frontend/assets/`.
- مهاجرت: `backend/bin/migrate.php`؛ CI: `.github/workflows/ci.yml`؛ انتشار: `.github/workflows/deploy-serviceyar.yml`.
- تست‌های HTTP روی پایگاه داده آزمایشی با `SERVICEYAR_TEST_DATABASE=1` و آدرس loopback اجرا می‌شوند.

## قاعده تغییر و پذیرش

۱. هر تغییر مالی همراه با تست مقدار قبل/بعد و سناریوی rollback باشد.
۲. هر API با شناسه شرکت یا مدرسه، scope را از نشست و مجوز سمت سرور تأیید کند.
۳. بازآرایی فایل‌های بزرگ صرفاً پس از ساخت تست پوششی انجام شود؛ جابه‌جایی گسترده کد بدون تست پذیرفتنی نیست.
۴. Migrationها روی بانک آزمایشی هم‌ساخت تولید اجرا شوند؛ قبل از انتشار نسخه پشتیبان مستقل تهیه شود.
۵. موفقیت تست CI و workflow deploy، به‌تنهایی تأیید نسخه زنده نیست؛ health، build SHA و مسیرهای مهم باید جداگانه بررسی شوند.

## فرمان‌های تست

```sh
node tests/tenant-identifier-contract.cjs
node tests/api-route-guard-contract.cjs
# در محیط اختصاصی آزمایش (نه دیتابیس تولید):
SERVICEYAR_TEST_DATABASE=1 node tests/api-integration.mjs
```

آزمون یکپارچه به دیتابیس تست دارای Migrationها و سرور محلی احتیاج دارد. نتیجه آن فقط از خروجی CI یا اجرای واقعی قابل تأیید است.
